01
What is an SRS?
Read this first. It's the agreement we make before writing any code.

An SRS (Software Requirements Specification) answers one question before development starts: what exactly are we building? Real companies write one so that developers, designers, and testers all agree on the same thing. You'll see these documents in every job.

Key Concept

Functional requirements (FR) describe what the app does. Example: "The user can shorten a link."

Non-functional requirements (NFR) describe how well it does it. Example: "The redirect should feel instant."

💡

If something isn't written in this document, we are not building it today. That keeps the project small enough to finish, and finishing is the whole point.

"The redirect should respond in under 300 ms." Which type of requirement is this?

02
Introduction
Purpose, scope, and who uses the app

Purpose

Long URLs are ugly, hard to read, and break when you paste them in messages. URL Shortener turns any long link into a 6-character short link, and counts how many times each short link was opened.

Scope

In scope (we build this)Out of scope (we don't)
Shorten a long URLLogin, signup, or user accounts
Redirect from the short link to the originalCustom short names (see Stretch goals)
Count clicks on each linkLink expiry (see Stretch goals)
List all links with their click countsCharts or analytics dashboards
Copy and delete linksRate limiting, admin panel

Users

There is only one type of user: anyone who opens the app. There is no login, so every link is visible to everyone using the app.

Functional requirements
What the app does. Each one has a clear "done when" so you know when to move on.
FR-1

Shorten a URL

The user enters a long URL and receives a short URL.

Done when

Submitting a valid URL saves it in the database and shows a short link like http://localhost:3000/aZ3kP9.

FR-2

Validate the URL

The server must reject bad input before saving anything. The frontend can check too, but the server is the one that decides.

Each bad input returns status 400 with its message, and the message appears under the input box.

Try it

This runs the same rules our server will. Type a URL or pick one of the examples.

    FR-3

    Generate a unique short code

    Each link gets a random 6-character code made from a–z, A–Z, and 0–9. That's 62 characters, so there are 62⁶ ≈ 56.8 billion possible codes. Before saving, the server checks that the code isn't already used, and generates a new one if it is.

    Done when

    No two links ever share the same code.

    Try it

    Each click picks 6 random characters from the 62 allowed ones, which is exactly what generateCode.js will do.

    FR-4

    Redirect using the short link

    Opening /:shortCode redirects the browser to the original URL with status 302. An unknown code shows a simple "This short link doesn't exist" page with status 404.

    Why 302 and not 301?

    Browsers remember 301 redirects permanently. The next time someone opens the link, the browser skips our server and goes straight to the original. With 302, every visit reaches our server, so every visit gets counted.

    Done when

    Opening a short link lands on the original page, and an unknown code shows the 404 page.

    FR-5

    Count clicks

    Every successful redirect increases that link's clicks by 1.

    Done when

    Opening a link 3 times shows 3 clicks in the list.

    FR-6

    View all links

    The home page lists every link, newest first, with the short URL, original URL, click count, and created date. When there are no links, it shows "No links yet. Shorten your first one above."

    Done when

    A newly created link appears at the top of the list without refreshing the page.

    FR-7

    Copy a short link

    Each short link has a Copy button. It copies the link to the clipboard and changes to "Copied!" for 2 seconds.

    Done when

    Pasting after clicking Copy gives the correct short URL.

    FR-8

    Delete a link

    Each link has a Delete button. It asks for confirmation, deletes the link, and updates the list.

    Done when

    A deleted link disappears from the list, and its short URL now shows the 404 page.

    Why do we redirect with status 302 instead of 301?

    05
    Non-functional requirements
    How well the app works: speed, reliability, safety, and how easy the code is to work with
    IDCategoryRequirementHow we achieve it
    NFR-1PerformanceRedirects feel instant (target: under 300 ms).A unique index on shortCode, so MongoDB finds the link directly instead of checking every document.
    NFR-2ReliabilityShort codes never repeat, and click counts stay correct even when many people click at once.A uniqueness check plus the unique index as a safety net. Clicks are updated with $inc, never read-then-save.
    NFR-3UsabilityOne simple page that works on mobile (360px and up), with visible feedback for every action.A loading state on the button, clear error messages, "Copied!" feedback, and a layout that stacks on small screens.
    NFR-4Security (basic)Only real web links are accepted, and secrets never reach GitHub.Allow only http: and https:, which blocks javascript: links that could run code. Keep .env in .gitignore.
    NFR-5MaintainabilityAnyone in the batch can open the project and find things fast.A fixed folder structure (model → controller → route), one job per file, and the same JSON response shape everywhere.
    NFR-6PortabilityThe project runs on any laptop with two commands.npm install and npm run dev on each side. Config comes from .env, and a .env.example is included.
    Why $inc and not find → clicks++ → save?

    If two people open the link at the same moment, both requests can read clicks: 4, both add 1, and both save 5. One click is lost. $inc tells MongoDB to add 1 inside the database in a single step, so simultaneous clicks are always counted.

    Why do we update clicks with $inc instead of find → clicks++ → save?

  "message": "Please enter a valid URL starting with http:// or https://"
}
    ⚠️

    Register /:shortCode last. It matches any one-segment path. If you later add a route like GET /health below it, Express will treat "health" as a short code and your new route will never run.

    Glossary
    Every new word in this project, in one line each
    TermMeaning
    Short codeThe 6 characters at the end of the short link (aZ3kP9)
    RedirectThe server telling the browser "don't show my response, go to this other URL instead"
    302HTTP status for a temporary redirect; the browser comes back to our server every time
    Location headerThe part of a redirect response that holds the URL the browser should go to
    $incA MongoDB operator that increases a number directly inside the database, in one safe step
    IndexA lookup table MongoDB keeps so it can find a document without checking every one
    CORSA browser rule that blocks a frontend from calling a different server unless that server allows it
    .envA file for config and secrets that is never pushed to GitHub
